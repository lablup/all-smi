## 요약

#353과 #361이 추가한 다중 GPU AMD 귀속 경로의 세 부분은 `cfg(target_os = "windows")`이면서 동시에 단일 GPU 호스트에서 도달 불가입니다. `plan_attribution`이 그중 무엇도 실행되기 전에 `SoleGpu` 분기를 타기 때문입니다. `loader::adapter_inventory`, `loader::sample_adapter`, `augment`의 `PerCard` 분기가 그것입니다. 어떤 단위 테스트도 여기에 닿지 않고 어떤 CI 잡도 all-smi를 Windows용으로 컴파일하지 않으므로, 이 코드는 검토만으로 배포되고 있었습니다. 동작한다는 증거는 손으로 쓰고 되돌린 임시 프로브에서 나왔습니다.

PR #371은 그 프로브를 영구적인 진단 검사로 만듭니다. `amd.adl.sensors`가 센서 인덱스 매핑에 대해, `amd.adl.adapters`가 `AdapterInfo` 레이아웃에 대해 하는 것과 같은 현장 검증 역할입니다. AMD GPU가 둘 이상인 호스트를 가진 사람은 이제 소스를 읽고 자기 프로브를 짜는 대신 명령 하나로 #370을 정리할 수 있습니다.

---

## 1. 문제 정의

카드별 귀속 작업에는 검증 비대칭이 있습니다. 다중 GPU 호스트에서 가장 중요한 코드가 정확히 단일 GPU 호스트가 실행할 수 없는 코드입니다. `plan_attribution`이 `SoleGpu`를 반환하고 단락시키므로, 인벤토리 호출, 인덱스별 샘플링, `PerCard` 보강 분기가 결코 실행되지 않습니다.

그래서 이들이 동작하는지 알 방법은 셋뿐이었습니다. 소스를 읽거나, 일회용 프로브를 쓰거나, 배포하고 기다리거나. 앞의 둘은 이미 한 번 하고 버렸으며, 이 PR이 멈추려는 것이 그 낭비의 반복입니다.

## 3. 기술적 선택과 그 이유

### 3.1 요약이 덤프에서 읽어 내게 두지 않고 판정을 직접 진술한다

이 검사는 인덱스마다 ADL 인덱스, PMLog 응답 여부, 해석된 판독값, 원시 `index=value` 쌍을 `amd.adl.sensors`가 이미 쓰는 무필터 방식으로 출력합니다. 출력은 물리 카드별로 bus/device/function과 인스턴스 경로와 함께 묶이므로, 카드가 둘인 호스트에서는 카드들이 다른지 한눈에 보입니다.

그러나 독자가 결론을 직접 끌어내야 하는 덤프는 오독되는 덤프입니다. 그래서 요약이 네 상태 중 무엇인지 직접 말합니다. **DISTINCT**, **IDENTICAL**, 응답한 카드가 너무 적을 때의 **판정 불가**, 단일 카드 호스트에서의 **관측 불가**입니다.

마지막 상태를 명시적으로 두는 것이 중요합니다. 카드 하나가 다섯 개의 디스플레이 출력 인덱스에 걸쳐 자기 자신과 일치한다는 것은 카드 두 개에 대한 증거가 아니며, 거기서 IDENTICAL을 보고하는 요약은 기술적으로 참이면서 실질적으로 오도합니다. 독자가 반증되기를 바라며 보는 바로 그 문자열이기 때문입니다.

### 3.2 `per_card_verdict`를 Windows 게이트 밖으로 빼 테스트 가능하게 했다

판정 로직은 `cfg(target_os = "windows")` 게이트 밖에 둔 자유 함수이므로 Linux 러너가 테스트합니다. 다섯 경우가 각 분기를 덮으며, 여기에는 세 카드 중 하나만 다른 혼합 사례가 포함됩니다. 순진한 전체 동일 비교라면 틀렸을 사례입니다.

이는 #361이 그룹화, 매칭, 개수 상한에 적용한 것과 같은 분리이며 이유도 같습니다. 운영자가 무엇을 결론 내릴지 결정하는 로직이 미검증으로 배포되는 부분이어서는 안 됩니다.

### 3.3 판독값 포매팅을 공유 `describe_readout`으로 이동

`amd.adl.per_adapter`와 `amd.adl.sensors` 둘 다 센서 판독값을 렌더링합니다. 두 덤프는 같은 구조체를 동일하게 렌더링할 때만 비교 가능하며, 독립된 두 호출 지점은 시간이 지나도 그것을 보장할 수 없습니다. 함수 하나는 보장할 수 있습니다.

### 3.4 모든 실패 경로가 추측 대신 skip 또는 warn

이는 모듈 나머지의 "추측 대신 거절" 자세와 같습니다. 인벤토리가 없으면 독자를 `amd.adl.adapters`로 안내합니다. 그 검사가 라이브러리 없음, 진입점 없음, 레이아웃 검증 실패를 구분하는 검사입니다. 추측하는 진단은 넘겨주는 진단보다 나쁩니다.

## 4. 검증 결과

**실하드웨어에서 검증했습니다.** AMD Radeon(TM) 8060S Graphics, Strix Halo APU, 드라이버 32.0.31035.1003, Windows 11 Pro 26200, 네이티브 `x86_64-pc-windows-msvc`:

- 어댑터 인덱스 5개 전부가 응답했고, 각각 16개 센서 표 전체를 반환했습니다.
- 한 카드의 인덱스들 사이에서 텔레메트리가 동일했으며, 이는 디스플레이 출력마다 인덱스 하나를 노출하는 단일 물리 GPU의 예상 형태입니다.
- 판정은 IDENTICAL을 주장하는 대신 이 호스트에서 카드별 구분이 **관측 불가**임을 올바르게 보고했습니다.

이 실행이 실제로 시험한 것은 마지막 항목입니다. 검사가 가용한 하드웨어에 대해 과잉 주장을 거절했습니다.

Linux 측 게이트: `per_card_verdict` 다섯 사례가 표준 러너에서 통과합니다.
