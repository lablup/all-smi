**일자**: 2026-08-23

**관련 항목**: PR #383, 이슈 #355  
**위험 수준**: 낮음 (도움말 텍스트와 회귀 테스트 1개)

## 요약

`all-smi service --help`가 서브커맨드의 실제 지원 범위와 어긋나 있었습니다. PR #383은 PR #321까지 배포된 백엔드 집합을 정확히 이름 짓고 `--user` 범위 문구를 바로잡도록 도움말을 갱신하고, 같은 어긋남이 다시 생기면 실패하는 회귀 테스트를 추가했습니다.

---

## 1. 문제 정의

#319, #320, #321을 거쳐 백엔드 셋이 배포됐습니다. Linux systemd, Windows SCM, macOS launchd입니다. 도움말 텍스트는 그중 마지막이 들어오기 전에 작성돼 여전히 launchd가 별도로 추적된다고 주장하면서 지원 목록에서 macOS를 빠뜨리고 있었습니다.

또한 `--user`를 설명하면서 어디에 적용되는지 말하지 않았습니다. `--user`는 사용자별 범위가 없는 Windows Service Control Manager에서 거부되므로, 도움말을 읽는 Windows 운영자는 도움말 자체로는 그것을 알 방법이 없었습니다.

도움말은 운영자가 한 번 실행하고 잊어버리는 서브커맨드의 일차 문서입니다. 잘못된 플랫폼을 나열한 문구는 이미 존재하는 백엔드를 위해 우회책을 만들도록 사람을 보냅니다.

### 변경 내용

- service 도움말이 Linux systemd, macOS launchd, Windows SCM을 지원 백엔드로 명시합니다.
- 같은 텍스트가 `--user`는 Linux와 macOS에 적용되고 Windows에는 적용되지 않음을 밝힙니다.
- 도움말이 다시 launchd가 별도 추적된다고 주장하거나 macOS 지원을 누락하면 실패하는 `src/cli.rs` 회귀 테스트를 추가했습니다.

## 3. 기술적 선택과 그 이유

### 3.1 회귀 테스트가 존재뿐 아니라 부재도 단언한다

새 문구가 나타나는지만 단언하면, 이후 편집이 낡은 문장 옆에 옳은 문장을 덧붙이는 것을 허용하게 됩니다. 그래서 테스트는 낡은 주장이 사라졌는지도 함께 단언하며, 이는 #351이 detail 키 규약에 쓴 것과 같은 형태입니다.

같은 파일이 소유하는 문자열을 테스트하므로 유지 비용이 싸고, 애초에 도움말 어긋남을 알아채는 유일한 장치입니다. 빌드의 다른 어떤 것도 도움말 텍스트를 실존 백엔드와 대조하지 않습니다.

### 3.2 Homebrew 영수증 업그레이드 경로는 명시적으로 범위 밖

2026년 8월 23일, tap의 `service do` 블록과 #310의 Homebrew 설치 바이너리 거부 경로를 이 저장소 밖에서 수동 검증했습니다.

service 블록 이전인 0.25.0 Homebrew 영수증 업그레이드 경로는 의도적으로 다루지 않았습니다. 다음 릴리스가 새 메타데이터를 실어 나를 것이기 때문입니다. 따라서 이 PR은 tap 리비전도, 기존 영수증을 위한 호환 우회책도 추가하지 않습니다. 그 판단은 성립했습니다. v0.26.0이 바로 다음 날 나갔습니다.
