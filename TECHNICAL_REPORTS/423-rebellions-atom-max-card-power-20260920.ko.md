# 기술 보고서: PR #423 - Rebellions ATOM Max 카드 전력

**날짜**: 2026-09-20
**상태**: 완료
**언어**: Rust, Markdown
**위험도**: 중간

---

## 요약

Rebellions 리더가 물리 카드 한 장의 전력을 다이 수만큼 중복해서 세던 것을 멈춘다. `rbln-stat`은 카드가 아니라 다이를 열거하고, 카드의 `card_power` 값을 그 카드의 모든 다이에 똑같이 적어 준다. 그래서 8장짜리 ATOM Max 노드(다이 32개)가 실제 341.5 W를 1369.7 W로 보고했다. 이제 `sid`로 다이를 카드로 묶고, 카드마다 한 다이만 전력을 보고하며 나머지는 `GPU_METRIC_UNAVAILABLE` 센티넬을 싣는다. 전력을 합산하는 모든 소비자가 카드를 정확히 한 번씩 센다. 자기 전력을 더 이상 표시하지 않게 된 행에도 카드 값은 보이도록, `card_power_watts` 디테일 키를 새로 추가했다.

---

## 1. 문제 정의

### 1.1 배경

Rebellions ATOM Max(`RBLN-CA25`)는 물리 카드 한 장에 다이 4개를 올리고, `rbln-stat --json`은 다이마다 항목 하나를 출력한다. 각 항목의 `card_power`는 보드 단위 전력이고, 같은 보드의 네 다이에 동일한 값이 반복된다. 리더는 다이마다 `GpuInfo`를 하나씩 만들면서 그 모두에 `card_power`를 `power_consumption`으로 넣었다. 보드 하나의 측정값이 장치 4개의 측정값으로 둔갑한 셈이다.

ATOM Plus(`RBLN-CA22`)는 카드당 다이가 하나라서 다이별 전력을 합해도 우연히 맞는다. 결함이 ATOM Max 노드를 실측하기 전까지 드러나지 않은 이유다.

### 1.2 기존 문제

- **모든 합계가 4배**: 실제 캡처 기준으로 8장짜리 ATOM Max 노드의 `total_power_watts`는 실측 341.5 W에 대해 1369.7 W였고, 같은 규모의 ATOM Plus 노드는 143.3 W에 대해 143.3 W였다.
- **평균이 맞아 보여서 결함을 가렸다**: `avg_power`가 부풀려진 합계를 장치 32개로 나눠 42.8 W를 내놓았는데, 이 값이 실제 카드당 전력과 같았다. 대시보드는 그럴듯하게 읽히고 합계만 4배 틀린 상태였다.
- **Prometheus도 같은 오류를 물려받았다**: 장치별 전력 시리즈가 다이마다 하나씩 나갔으므로, ATOM Max 호스트에서 `sum by (instance)`가 다이 개수만큼 부풀었다.
- **`sid`가 없으면 응답 전체가 실패했다**: 역직렬화에서 `sid`가 필수 필드였기 때문에, 장치 항목 하나가 어긋나면 해당 장치만이 아니라 호스트의 NPU 전체가 사라졌다.

### 1.3 위험 평가

| 위험 | 영향 | 발생 가능성 |
|------|------|-------------|
| 용량 산정과 전력 예산이 4배 부풀려진 클러스터 합계를 기준으로 움직인다 | 높음 | 높음 |
| `card_power`를 다이 수로 나눠 합계를 맞추면, "직접 측정값"이라는 계약을 가진 필드에 계산값이 들어간다 | 중간 | 중간 |
| 32행 중 24행에 전력이 비는 것이 올바른 회계가 아니라 리더 고장으로 읽힌다 | 중간 | 높음 |
| 다이 위치 기준으로 보고 다이를 고르면 폴링마다 바뀌어 uuid 기준 시리즈의 연속성이 끊긴다 | 중간 | 중간 |

## 2. 기술적 결정

### 2.1 카드마다 보고 다이 하나, 분할값도 행 병합도 아니다

이슈 #418은 선택지 셋을 메인테이너에게 제시했고, 이 PR은 (b)를 구현한다. (a), 즉 `card_power`를 카드당 다이 수로 나누는 안은 기각했다. `power_consumption`은 그 외의 모든 곳에서 직접 측정값이고, 1/4 분할값은 계산값이기 때문이다. (c), 즉 다이 4행을 카드 1행으로 접는 안도 기각했다. 사용자가 보는 장치 수가 바뀌고, 지금 다이당 한 행으로 이미 정확한 다이별 메모리를 카드 단위로 다시 합산해야 한다(32 x 15.72 GiB로 하드웨어와 일치한다).

(b)는 새로 만들 기계장치가 없다. `src/metrics/gpu_readings.rs`의 `total_power_watts`가 `filter_map`으로 부재 값을 이미 건너뛰므로, 네 다이 중 셋을 부재로 표시하면 남은 값이 전부 실측값인 채로 합계가 맞는다.

### 2.2 보드 시리얼인 `sid`로 묶는다

`sid`는 `rbln-stat --json`에서 두 변형 모두에 대해 물리 카드 하나당 그룹 하나를 만들어 주는 유일한 필드다. `group_id`는 ATOM Plus 장치 8개를 전부 한 그룹으로 접고, `location`은 카드 색인이 아니라 보드 안의 다이 위치이며, `npu`는 ATOM Max에서 카드당 한 번씩 반복된다. `sid`가 비었거나 없는 장치는 맞출 형제가 없으므로 그 자체로 카드 하나로 취급한다. 필드에는 `#[serde(default)]`를 붙여, 값이 없어도 응답 전체가 실패하지 않게 했다.

### 2.3 보고 다이는 목록의 첫 항목이 아니라 커널 색인이 가장 낮은 다이다

카드 안에서 `card_power_roles`는 커널 장치 이름에서 파싱한 색인이 가장 낮은 다이를 고른다(`rbln12`는 12). 파싱되지 않는 이름은 파싱되는 모든 이름 뒤로 정렬되고, 동률이면 `rbln-stat`이 나열한 순서로 되돌아간다.

위치만 쓰는 방식은 기각했다. `rbln-stat`은 장치를 색인 순으로 나열하지 않는다. ATOM Plus 캡처는 rbln0, rbln2, rbln3 순으로 읽힌다. 또한 보고 다이가 폴링 사이에 옮겨 다니면 안 된다. 전력 시리즈와 에너지 카운터 키가 모두 장치 uuid 기준이고, 둘 다 폴링 사이에 이어져야 하기 때문이다.

### 2.4 벤더 중립 키 `card_power_watts`, 이름을 `power`로 하지 않은 이유

카드 값은 다이가 여럿인 카드의 모든 다이에 디테일 항목으로 실리고, 이는 장치 식별 시리즈의 레이블이 된다. 키를 snake_case로 쓴 것은 의도다. 모든 디테일 키는 `sanitize_label_name`을 거치는데 snake_case는 그대로 살아남으므로, 로컬 리더가 쓰는 문자열과 원격 파서가 저장하는 문자열이 같아진다. 기존 `power_limit_max`와 같은 방식이다.

키 이름을 `power`나 `power_draw`로 하면 안 된다. 범용 NPU 익스포터가 그 이름을 `all_smi_npu_power_watts`와 `all_smi_npu_power_draw_watts` 시리즈로 바꿔 해당 키를 가진 모든 장치에 내보내므로, 원래 결함이 다른 시리즈를 통해 되살아난다.

### 2.5 다이가 하나인 카드는 키를 달지 않는다

ATOM Plus 장치는 모두 그 자체로 카드 하나이고 `power_consumption`이 이미 카드 값이므로, `card_power_watts` 레이블을 붙이지 않는다. 모든 장치에 일률적으로 붙이는 대안은, 애초에 이 버그와 무관한 ATOM Plus 사용자에게 폴링마다 식별 시리즈가 바뀌는 비용을 지운다. 그 비용은 ATOM Max에서만 받아들인다. Tenstorrent가 이미 `detail`에 실시간 전류와 클럭을 싣고 같은 일을 하고 있다.

## 3. 구현 내용

### 3.1 리더: 역할은 폴링 전체를 보고 정한다

`card_power_roles`는 응답당 한 번 돈다. 한 다이의 역할이 형제 다이에 달려 있기 때문이다. 장치마다 `CardPowerRole`을 돌려주는데 필드는 둘이다. `reports_card_power`는 카드당 정확히 한 다이에서만 참이고, `shared_card_watts`는 보고 다이가 파싱한 값으로 다이가 여럿인 카드의 모든 다이에 실린다.

```rust
let power = if role.reports_card_power {
    parse_power_safe(&device.card_power)
} else {
    GPU_METRIC_UNAVAILABLE
};
```

카드 값은 게시 전에 검증한다. `parse_power`를 거친 뒤 유한하고 음수가 아닌지 거른다. 보고 다이의 값이 파싱되지 않으면 자리표시자를 넣는 대신 `card_power_watts`를 아예 게시하지 않는다.

첫 커밋 `cd7ab44`는 `gpu_info_from_response`를 분리해, `rbln-stat`을 실행하지 않고도 폴링의 변환 단계를 테스트가 그대로 구동할 수 있게 했다. 두 번째 이후 폴링만 타는 정적 캐시 경로까지 포함된다.

### 3.2 합계를 쓰는 쪽

`src/metrics/gpu_readings.rs`에 `mean_power_watts`를 추가했다. 전체 행이 아니라 보고한 행 수로 나눈다. `MetricsAggregator::aggregate_gpu_metrics`는 같은 필터를 직접 적는 대신 이 함수를 호출하고, `draw_system_view`는 대시보드의 Avg. Power에 이를 쓰면서 아무도 보고하지 않으면 `0.0W`가 아니라 `N/A`로 렌더링한다. Apple Silicon은 이전 의미, 즉 GPU 행 하나가 담은 CPU+GPU+ANE 합산값을 유지한다.

로컬 수집기의 `inject_gpu_power`는 `power_consumption`을 날것으로 합산하고 있었다. 센티넬이 `-1.0`이므로 조용한 다이마다 1 W씩 빼는 셈이었다. 이제 부재 값을 거르는 `total_power_watts`를 호출한다.

### 3.3 표시와 원격 왕복

자기 측정값이 없는 다이는 카드 값을 괄호에 넣어 렌더링한다(예: `Pwr:   (43W)`). 카드의 모든 다이가 자기 보드의 소비량을 보여 주되, 괄호가 "이 행 자신의 측정값이 아니고 어떤 합계에도 들어가지 않는다"는 표시가 된다. 카드 값이 유효하지 않으면 그대로 `N/A`로 나온다.

원격 메트릭 파서는 `card_power_watts`를 `detail`에 저장하는 식별 레이블 목록에 포함하도록 확장했다. 원격 뷰어도 로컬과 같은 괄호 값을 본다.

### 3.4 익스포터는 원래부터 옳았다

이슈 #418은 `all_smi_npu_power_watts`가 중복 계산된다고 적었다. PR은 이를 바로잡는다. Rebellions는 그 시리즈를 애초에 내보내지 않는다. 장치별 시리즈는 `all_smi_gpu_power_consumption_watts`이고, 이미 측정값이 부재인 행을 빼고 내보내므로 익스포터는 손댈 것이 없었다. 스냅샷 JSON과 CSV, record/replay는 비보고 다이를 기존 센티넬 계약대로 `power_consumption: -1.0`으로 직렬화하고, 스냅샷 Prometheus는 아예 생략한다.

## 4. 배운 점

### 4.1 부재 센티넬은 매직 넘버가 아니라 계약이다

이 수정이 통하는 이유는 `GPU_METRIC_UNAVAILABLE`이 중요한 곳에서 이미 "측정하지 않음"을 뜻했고, 집계 헬퍼들이 이미 그것을 존중했기 때문이다. 고쳐야 했던 곳은 헬퍼를 우회하던 둘뿐이었다. `inject_gpu_power`의 날것 `.map(...).sum()`과 집계기에 직접 적혀 있던 보고 행 수 계산이다. 프로젝트에 부재 인코딩이 있다면, 점검할 대상은 헬퍼를 거치지 않고 필드를 직접 합산하는 코드다.

### 4.2 레이블 이름 하나가 그 레이블이 설명하는 버그를 되살릴 수 있다

새 디테일 키를 `power`로 이름 짓는 것이 가장 자연스러운 선택이었고, 그랬다면 범용 NPU 익스포터를 먹여 네 다이 모두에 장치별 전력 시리즈가 다시 생겼을 것이다. 레이블 이름 공간과 메트릭 이름 공간은 익스포터의 이름 기반 규칙으로 이어져 있으므로, 디테일 키는 표시 문자열이 아니라 인터페이스 결정이다.

### 4.3 맞아 보이는 평균이 틀린 합계를 감출 수 있다

평균이 42.8 W로 맞게 읽힌 것은 중복 계수와 행 수가 같은 숫자였기 때문일 뿐이다. 하나의 틀린 합계에서 나온 파생값 둘이 이상 여부를 두고 서로 다른 답을 낼 수 있고, 맞아 보이는 쪽은 증거가 아니다. 평균의 분모를 같은 변경에서 보고 행 기준으로 옮겨야 했던 이유이기도 하다. 합계만 고쳤다면 평균이 반대 방향으로 같은 배수만큼 틀렸을 것이다.

## 6. 검증과 후속

### 완료한 검증

- 회귀 테스트는 수정 전 리더에서 `total NPU power 1366 W, expected 341.5 W`로 실패하고, 수정 후 통과한다.
- 리더 테스트 25개 통과, 그중 10개가 신규다. 회귀, 순서 변경에도 유지되는 보고 다이, ATOM Plus 무변경, 다이별 메모리, `sid` 누락과 공백, 전력 시리즈 8개가 341.5 W로 합산되며 센티넬도 `all_smi_npu_power_watts`도 없는 `/metrics` 렌더링, 341.5 W로 돌아오는 원격 왕복을 덮는다.
- 커밋 트리에서의 필터 실행: 리더와 변경된 모든 모듈에 대한 `cargo test --lib` 154개 통과, 여기에 로컬 수집기 테스트를 더한 `cargo test --bin all-smi` 93개 통과, `cargo test --test user_facing_text_test` 5개 통과.
- 최종 트리에서의 전체 실행: `cargo test --bin all-smi` 1849개 통과. `cargo test --lib`는 1667개 통과에 2개 실패였고, 둘 다 이 PR이 건드리지 않은 `storage::disk_cache`의 타이밍 테스트로 단독 실행과 bin 타깃에서는 통과한다.
- `cargo clippy --lib --tests -- -D warnings`와 `cargo fmt --check` 무경고. 프리커밋 훅의 `cargo clippy --all-targets --all-features -- -D warnings`가 두 커밋 모두에서 통과했다.
- `9e68dbd` 기준 CI: Build Check, Test Suite, launchd 및 systemd 스모크 테스트, Packaging Sync Check, CLA 모두 통과.

### 완료 필요

- 실제 ATOM Max 캡처가 확보되면 `tests/fixtures/rbln-stat-atom-max-synthetic.json`을 교체한다. 현재 픽스처는 합성이다. `sid` 8개에 다이 4개씩, 카드 전력 합이 341.5 W이고, ATOM Plus 캡처와 똑같은 형태로 작성했다. 이슈 #418은 실제 캡처를 언급하지만, 여기에 들어간 파일은 그것이 아니다.
- ATOM Max와 ATOM Plus 하드웨어에서 확인한다. 둘 다 없었기 때문에 동작 전체가 픽스처로만 고정되어 있다.

### 남은 제약

- `card_power_watts`는 메인테이너가 뒤집을 수 있는 해석이다. 다이가 하나인 카드, 즉 ATOM Plus 전체는 의도적으로 이 키를 달지 않는다.
- ATOM Max에서는 레이블이 실시간 값을 싣기 때문에 다이마다 `all_smi_gpu_info` 시리즈가 폴링마다 바뀐다.
- Users 탭은 프로세스에 전력을 귀속시킬 때 부재 측정값을 0 W로 고정하므로, 비보고 다이에서 도는 프로세스에는 카드 전력이 귀속되지 않는다.
- 의도적으로 두고 온 부분: `parse_power_safe` 내부의 `0.0` 폴백, 그리고 ATOM Max에서 모호한 컨텍스트 대 장치 조인.
